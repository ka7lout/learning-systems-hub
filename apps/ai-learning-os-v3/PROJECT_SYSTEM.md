# Project system

## Ladder
L1 Python engineering · L2 data analysis · L3 SQL/data pipeline · L4 classical ML · L5 sequence
modelling · L6 CV/NLP · L7 LLM/RAG · L8 agents · L9 production AI · L10 research and capstone.
All 21 original projects are present and mapped onto this ladder.

## Data policy
Real public data or real public APIs where lawful. Each project records source, licence/terms,
acquisition date, schema, known limitations, bias risks, leakage risks and reproducibility notes.
Dataset links point at repository/search landing pages with an instruction to record the exact URL,
licence and download date — the platform does not assert that a specific dataset file still exists.
Synthetic data is allowed only for explicit synthetic-data lessons or deterministic tests, and is labelled.

## Execution
The platform never executes learner code. Compute belongs in GitHub Codespaces, local development,
Colab or Kaggle. The platform owns the brief, constraints, milestones, definition of done, evidence
record, evidence classification and portfolio linkage. GitHub is the source of truth for code.

## Definition of done
Requirements met · tests pass and edge cases considered · data provenance documented · evaluation design
valid · failure analysis written · reproducible README · security and privacy review · limitations
stated. Deployment-class projects add: reachable deployment (or documented non-deployment), monitoring
signals with thresholds, and a tested rollback procedure.

## Evidence classification (computed, never declared)
Practice Only → Skill Evidence (repository) → Technical Artifact (≥50% DoD) → Portfolio Project (≥80% DoD
and done) → Professional Evidence (100% DoD + deployment) → Signature Project (as above at ladder ≥9).
Completing a project with a repository writes weighted project evidence into the skill graph, which is
what unlocks mastery level 8.
